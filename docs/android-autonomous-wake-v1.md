# 手机端自主唤醒 V1（第一阶段）

本阶段只实现手机本地事件入口、持久化队列和模拟通知，为后续 Ash Agent Core 留出接入点。没有模型请求、事件上传、Render 变更或 MCP 接口变更。

## 原实现与改动

- 原 `CompanionService` 是 `START_STICKY` 前台远程命令轮询；`ScreenshotService` 有看门狗和仅在前台服务不运行时工作的既有兜底轮询。沿用这两条路径，没有新增网络轮询。
- 原看门狗对 `user_stopped` 的缺省值与兜底轮询不一致。现在统一通过 `AppPrefs.serviceRequested` 判断，首次安装默认为停止；只迁移明确的旧启动状态。
- 手动启动/停止同步提交状态并递增会话代数。停止后不会因 sticky 重建、定时广播、无障碍看门狗、开机或更新自动复活；停止前发出的网络请求不能在新会话中执行返回命令。已经开始执行的远程动作无法撤销。
- Android 11+ 在新进程入口检查最近的 `ApplicationExitInfo.REASON_USER_REQUESTED`；若晚于最近一次手动启动，则视作系统任务管理器/强行停止，要求用户重新启动。厂商未提供退出历史时只能依赖应用已保存的停止状态。
- `WakeRuntime` 归属于原前台服务。系统广播和原轮询迭代触发有界队列处理；本地模式不启动网络轮询线程。没有常驻 WakeLock，单次本地处理最多持有 10 秒锁，不包含网络工作。

## 前台服务兼容策略

minSdk 23、targetSdk 34 保持不变，不改变发布版本号或签名。

| 系统 | 类型 / 恢复策略 |
| --- | --- |
| Android 6–9 | 既有前台服务兼容入口 |
| Android 10–13 | 显式 `dataSync` 类型，保留现有兼容路径 |
| Android 14+ | 显式 `specialUse`，声明用户主动开启的常驻远程命令监听与本地事件分发用途；不把长期监听声明为无限期数据传输 |
| Android 15+ | 实现系统前台服务超时回调，停止并标记待用户恢复，不启动绕过限制的重启循环 |

`specialUse` 仍需满足系统和分发渠道政策；如果通过 Google Play 分发，需要提交对应用途说明并通过审核，不能视为审核已通过。这里的用户可见功能是持续的远程手机命令监听与自主事件分发，不是后台 AI 常驻推理。

恢复仅在系统允许时尝试：

1. 用户主动启动后，系统可通过 `START_STICKY` 异常重建服务。
2. “允许开机 / 更新后恢复”默认关闭；开启后，已启动且未手动停止的服务可在 `BOOT_COMPLETED`（解锁后）或 `MY_PACKAGE_REPLACED` 恢复。
3. 后台启动被拒绝时持久化待恢复状态，不让看门狗反复强拉；用户打开应用可在可见状态重试。
4. 定时广播不凭借普通非精确闹钟强行启动前台服务。没有服务时只保存事件；进程必须由允许的恢复入口或用户启动后才消费。
5. 不接收直接启动广播，不申请精确闹钟权限，不承诺厂商杀后台、强行停止、Doze 下的实时性。系统“强行停止”期间可能不投递事件，无法补采未收到的屏幕变化。

## 队列语义

`WakeQueue` 使用应用私有 SQLite 数据库 `autonomous_wake_v1.db`。接受事件先持久化，再发送通知，最后提交本地完成与冷却状态。保存字段包括唯一去重键、类型、最小化载荷、优先级、创建时间、下次重试时间、尝试次数、本地状态、同步状态和错误类别。

- 屏幕开/关：动态系统广播，同类 30 秒窗口去重。
- 电量：按 10% 档位或充电状态变化采集；持久化上次采集状态，合并 sticky 重复广播。
- 定时：约 15 分钟周期，使用 `setAndAllowWhileIdle` 非精确闹钟；系统节流和 Doze 可以延迟投递。重试和冷却复用这一闹钟，不添加另一条轮询。
- 应用使用：默认关闭，只监听已授权无障碍服务的窗口切换，且仅限用户设置的目标 App，同 App 每分钟去重。复用现有权限，不新增 UsageStats 轮询，不保存屏幕文字。
- 模拟：独立事件 ID，优先级最高；电量低优先于普通定时/屏幕/App 事件。相同优先级按创建顺序处理，每轮最多 4 条。
- 通知不可用时，从 30 秒开始指数退避，最大 6 小时，不因达到重试次数而删除事件。闹钟的实际调度最早为一分钟后，仍受系统节流影响。
- 本地成功后同类事件冷却 60 秒；冷却阻止的是处理，不删除后续事件。
- 免打扰默认开启，按设备本地时间 23:00–08:00 保留待处理事件，到允许时段再消费。系统自身的通知免打扰仍然生效。
- 队列总容量 10000 条（包括已完成但待同步的记录）；满时拒绝新事件并显示持久状态，不淘汰已接收记录。V1 没有自动清空或清理待同步记录的功能，长期使用前需要后续同步/归档策略。

通知以持久化行 ID 生成稳定 tag，并设置 `onlyAlertOnce`。进程在通知后、完成提交前崩溃，会重放相同通知身份，替换仍存在的通知。SQLite 与系统通知不能跨进程事务提交，因此不承诺严格 exactly-once；若用户已划掉通知，极窄崩溃窗口可能重新出现。后续 AI/同步适配器必须使用稳定事件 ID 实现幂等。

`state=delivered` 只表示本地模拟通知已提交；`sync_state=pending` 始终保留。网络断开不影响 SQLite 写入，网络恢复也不会重放已经完成的本地通知。**V1 没有真实同步适配器，因此“断网→联网后服务器只执行一次”的端到端验收尚不适用，不能宣称已经验证。**

## 用户操作

设置 → 自主唤醒：开启总开关，按需调整免打扰、开机/更新恢复、目标 App 事件及调试日志，再点击“手动启动”。本地模拟模式不要求填写服务器、Token 或开启无障碍权限；真实远程功能仍使用用户原有连接和权限。

“模拟唤醒 / 本地通知”先入队；通知权限关闭或免打扰时保留待处理。可以刷新队列状态、查看现有本机调试日志。日志默认关闭，不记录 Token、屏幕内容或完整事件载荷。

“手动停止（含远程监听）”或常驻通知中的“停止”会停止共享前台服务，连同其远程轮询；不会关闭用户已授权的系统无障碍权限。只关闭自主唤醒总开关则暂停事件消费并取消闹钟，不关闭现有远程服务、不清空队列。

## 构建与自动测试

需要 JDK 17、Android SDK platform 34、build-tools 34.0.0、Maven 3.9.x。SDK/JDK 的安装路径由本地环境决定，不把密钥或本机代理配置写进仓库。

```bash
export JAVA_HOME=/path/to/jdk-17
export ANDROID_HOME=/path/to/android-sdk
export PATH="$JAVA_HOME/bin:$PATH"
bash android/build.sh
mvn -B -C -f android/tests/pom.xml test
```

测试先依赖 APK 构建生成的 `android/build/gen` 中的 R 类。Maven 固定 Robolectric/JUnit 版本，通过正式 Maven/Google 仓库获取依赖；提前准备 Android 运行时 jar，测试阶段使用离线 Robolectric 解析，避免运行时另外下载。测试在 JVM 中执行真实的 Android SQLite、通知和服务适配代码（Robolectric 环境），不连接生产端点。

现有 Android GitHub Actions 工作流在 APK 构建后执行同一测试命令；需要 PR 中的 Actions 实际运行后才能认定 CI 通过。APK、签名侧车和测试输出均被忽略，不提交构建产物或任何凭据。

| 远程回归 | 使用用户自己的测试服务与测试手机，验证状态、截图、无障碍操作和命令回执；不使用 Render 生产实例 |

本次云机器没有真机或 KVM；不能把 Robolectric 的测试结果等同于上述设备验收。物理锁屏、系统重启、厂商保活、真实手机截图及远程操作均保留为发布前检查。
